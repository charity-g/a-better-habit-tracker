**Critique of your proposed improvement plan**

Your plan is directionally strong. The boundary you drew is mostly right:
- Global/shared state for sync status, pending queue, online/offline, and recent entries is correct.
- Local component state for timer controls and transient form fields is also correct.
- Manual submit feeding pending queue is already aligned with current flow: add entry as pending then queue sync, via db.ts, db.ts, db.ts, plus background sync registration in useHabitTracker.ts.

Where I would adjust your plan:
- “Modify a local .json file” in browser is not realistic at runtime for a web app. Use IndexedDB/localStorage for user-modifiable settings and keep compile-time defaults in code or static JSON loaded at build time.
- Keep auth state minimal in global store: connected/disconnected, token expiry metadata, last auth error. Avoid broad token exposure to UI tree.
- Split hook into layers:
1. Data/sync/auth store hook (shared, global-ish)
2. UI draft hooks for manual form and timer (local)
3. Pure selectors for today/yesterday summaries

---

**Should you use Redux?**

Short answer: **No, not yet.**

You do not need Redux for this size/scope. A simpler setup is better:
1. Keep IndexedDB as source of truth for entries/settings/queue.
2. Use one shared hook + context (or lightweight store like Zustand) only for cross-cutting sync/auth/network status.
3. Keep timer/manual form state inside components.
4. Derive “today/yesterday/recent” via memoized selectors.

Use Redux only if you hit clear pain: many unrelated components mutating shared state, hard-to-trace updates, or complex middleware needs.

---

**Security implications of browser-stored Google auth + logout**

- Browser-stored access tokens are vulnerable to XSS theft. Main mitigation is preventing XSS and minimizing token lifetime/scope.
- Use least privilege OAuth scope, short-lived tokens, and avoid storing refresh tokens in browser.
- Logout should clear local token (you already do this in sync.ts).
- For stronger security, move Google Sheets writes to a backend and keep OAuth secrets/tokens server-side.
